GAP Ports missing from the table

  • 445 — SMB. The lateral-movement and ransomware port (EternalBlue/WannaCry). Highest-yield of the three.
  • 137–139 — NetBIOS (name service, datagram, session). Legacy Windows file/printer sharing.
  • 3268 — LDAP Global Catalog (3269 for the TLS version).
  • Every other exam port is already on the home-page master table.

2.5 Hardening techniques

  • The enumerated list CompTIA expects you to recognize — and the thinnest spot in these notes (0 practice questions on default passwords).
  • Change default passwords — the single most-tested hardening step for IoT, network gear, and ICS.
  • Disable unnecessary ports and protocols — shrinks the attack surface; the flip side of "open service ports" as a vector in 2.2.
  • Remove unnecessary software (debloating).
  • Install endpoint protection (EDR/AV) · host-based firewall · HIPS.
  • Encryption of the host itself.
  • Exam cue: a newly deployed device, an IoT fleet, or an unpatchable system wants change defaults and disable unused services before anything sophisticated.

5.3 Vendor selection

  • Due diligence — investigating a vendor's security posture, finances, and track record before signing.
  • Conflict of interest — a vendor relationship that compromises impartial judgment (e.g. the auditor also sells you the remediation). Appears nowhere else in these notes.
  • Do not confuse those with vendor monitoring (ongoing) or vendor assessment (pen test, right-to-audit clause, independent assessments, supply chain analysis).

Domain 2 — Threats, Vulnerabilities & Mitigations

22% of the exam — the second-heaviest domain

2.1 Threat actors & motivations

  • Nation-state — highest resources and sophistication; the APT. Motives: espionage, war, service disruption.
  • Unskilled attacker — runs other people's tools. Motive: disruption/chaos.
  • Hacktivist — philosophical/political. Defacement, leaks, doxxing.
  • Insider threat — already has access, so hardest to detect. Motives: revenge, financial gain.
  • Organized crime — well-funded and professional. Motive: financial gain (ransomware).
  • Shadow IT — not malicious; employees deploying unsanctioned tech, creating unmanaged attack surface.
  • Compare actors on three attributes: internal vs external · resources/funding · sophistication.

2.2 Vectors & social engineering

  • Same trick, different channel: phishing (email) · vishing (voice) · smishing (SMS).
  • Spear phishing targets a specific person; whaling targets executives.
  • BEC — business email compromise; a spoofed or hijacked executive account requesting an urgent wire transfer.
  • Pretexting — an invented scenario that justifies the ask.
  • Watering hole — compromise a site the target group already visits.
  • Typosquatting — lookalike domain. Brand impersonation — lookalike sender.
  • Misinformation = false. Disinformation = false on purpose.
  • Non-human vectors: removable device (BadUSB), unsupported systems, unsecure networks, open service ports, default credentials, supply chain (MSP, vendor, supplier).

2.3 Vulnerability types

  • Race condition / TOC-TOU — state changes between time of check and time of use.
  • Buffer overflow — writing past allocated memory; memory injection puts code into a running process.
  • VM escape — breaking out of a guest onto the hypervisor. Resource reuse — another tenant's leftover memory/storage.
  • Side loading — installing apps outside the official store. Jailbreaking/rooting — removing OS restrictions.
  • Legacy / end-of-life — no vendor patches exist at all.
  • Zero-day — no patch and no signature, so signature-based tools miss it. Behavior-based detection is the answer.

2.4 Malware & indicators

  • Worm self-propagates with no user action; a virus needs a host file or a click.
  • Logic bomb triggers on a condition/date. Rootkit hides at kernel level. Bloatware is unwanted preinstalled software.
  • Password spraying — one common password against many accounts, specifically to avoid lockout. Brute force hammers one account.
  • Impossible travel — logins from two distant places too close in time. Classic credential-compromise indicator.
  • Missing logs / out-of-cycle logging — evidence of an attacker covering tracks.
  • Other indicators: account lockout, concurrent session usage, blocked content, resource consumption, resource inaccessibility.
  • Crypto attacks: downgrade (force a weaker protocol) · collision · birthday.

2.5 Mitigation techniques

  • Segmentation — the default correct answer for anything that cannot be patched (ICS, legacy, medical).
  • Isolation — fully cut off; stronger than segmentation.
  • Application allow list — only approved software runs (deny-by-default). Far stronger than a block list.
  • Least privilege · ACLs and permissions · patching · encryption · monitoring.
  • Configuration enforcement — continuously push devices back to the approved baseline.
  • Decommissioning — retire the asset properly rather than leave it running unmanaged.

5.2 Risk math

  • SLE = AV × EF Single Loss Expectancy = Asset Value × Exposure Factor (the % of the asset destroyed by one event).
  • ALE = SLE × ARO Annualized Loss Expectancy = SLE × how many times per year.
  • ARO is a rate: once every 4 years = 0.25.
  • A control is worth buying only if it costs less than the ALE reduction it delivers.
  • Qualitative = high/medium/low judgment. Quantitative = dollars and these formulas.

1.2 Zero Trust planes

  • Control Plane — decides. Policy Engine makes the grant/deny decision; Policy Administrator issues the token/credential that carries it out. Also here: adaptive identity, threat scope reduction, policy-driven access control.
  • Data Plane — does. Policy Enforcement Point is the gate that actually allows or blocks traffic. Also here: implicit trust zones, subject/system.
  • Exam trap: Engine decides, Administrator issues, PEP enforces.

1.2 Deception & disruption

  • Honeypot — one decoy system.
  • Honeynet — a decoy network of honeypots.
  • Honeyfile — bait file (e.g. "passwords.xlsx") that alerts when opened.
  • Honeytoken — fake data/credential planted so any use of it proves a breach and traces the path.
  • Scale cue: token → file → pot → net.

4.7 Automation & orchestration

  • SOAR — Security Orchestration, Automation, and Response. Runs playbooks; SIEM detects, SOAR acts.
  • Guardrails — automated policy limits that stop unsafe configurations from ever deploying.
  • Use cases: user/resource provisioning, ticket creation, escalation, enabling/disabling services, CI/CD testing, APIs.
  • Benefits: efficiency, enforcing baselines, secure scaling, faster reaction, workforce multiplier.
  • Downsides: complexity, cost, single point of failure, technical debt, ongoing supportability.

3.1 ICS / SCADA / embedded

  • ICS industrial control systems; SCADA supervises them across sites; PLC is the device doing the work.
  • RTOS — real-time OS, guarantees timing. Used in medical, automotive, aviation.
  • Shared weakness: cannot be patched or taken offline. Correct answers are almost always network segmentation, air-gapping, or compensating controls — not "apply the patch."

1.4 Crypto modes & PFS

  • ECB — never use; identical plaintext blocks produce identical ciphertext (leaks patterns).
  • CBC — chains blocks with an IV; confidentiality only.
  • GCM — the one to pick: confidentiality + integrity/authentication (AEAD).
  • Perfect Forward Secrecy comes from ephemeral key exchange — DHE / ECDHE. Stealing the server's private key later cannot decrypt past sessions.

5.5 Audits & pen testing

  • Known environment = full info (old white box). Partially known = some (gray). Unknown = none (black).
  • Offensive = red team. Defensive = blue team. Integrated = purple (both, together).
  • Passive recon — no contact with the target (OSINT, WHOIS, social media). Active recon — scanning, enumeration; it can be detected.
  • Attestation = a formal signed statement that controls are in place.

5.3 Agreement types

  • SLA — measurable performance/uptime commitments.
  • MOU — non-binding statement of intent.
  • MOA — more formal than an MOU; can be binding.
  • MSA — master terms governing all future work.
  • SOW / WO — the specific deliverables under an MSA.
  • NDA — confidentiality.
  • BPA — terms of a business partnership.

4.8 Forensics & volatility

  • Order of volatility — collect most-perishable first: registers/cache → RAM → swap → disk → remote logs → archive
  • Legal hold — the duty to preserve data once litigation is anticipated. Comes first.
  • Chain of custody — who touched the evidence, when, and why. Broken chain = inadmissible.
  • IR order: Preparation → Detection → Analysis → Containment → Eradication → Recovery → Lessons Learned.

5.2 BIA metrics

  • RTO — how fast you must be back up (time to restore).
  • RPO — how much data you can afford to lose (drives backup frequency).
  • MTTR — mean time to repair.
  • MTBF — mean time between failures (reliability).
  • Trap: a 4-hour RPO means back up at least every 4 hours; it says nothing about how long recovery takes.

1.4 Certificate lifecycle

  • CSR — request you send to the CA; carries the public key.
  • CRL — periodically downloaded list of revoked certs.
  • OCSP — real-time single-cert revocation query.
  • OCSP stapling — the server attaches a fresh signed status, so the client need not ask the CA.
  • Wildcard (*.site.com) covers subdomains; SAN covers multiple distinct names.
  • Key escrow — a third party holds a copy of the key.

4.5 Email authentication

  • SPF — DNS record listing which IPs may send for the domain.
  • DKIM — cryptographic signature proving the message was not altered.
  • DMARC — ties SPF+DKIM together: sets the policy (none/quarantine/reject) and gets reports.
  • Order to remember: authorize → sign → enforce.

3.4 Backups

  • Full — everything, every time. Slow backup, fastest restore.
  • Incremental — since the last backup of any kind. Fastest backup, slowest restore (full + every increment).
  • Differential — since the last full. Slower backup, faster restore (full + one differential).
  • 3-2-1 — 3 copies, 2 different media, 1 offsite.
  • Sites: hot = running now · warm = hardware ready, data stale · cold = empty space.

1.1 Control categories vs types

  • Categories (who/what runs it): Technical · Managerial · Operational · Physical.
  • Types (what it does): Preventive · Deterrent · Detective · Corrective · Compensating · Directive.
  • Directive is the one most often forgotten — it instructs (policy, signage, procedure).
  • Deterrent discourages (warning sign); preventive stops (lock).

4.1 Wireless & EAP

  • WPA3 — uses SAE (Simultaneous Authentication of Equals) to replace the WPA2 pre-shared key handshake; blocks offline dictionary attacks.
  • EAP-TLS — certificates on both sides. Strongest, most work.
  • PEAP / EAP-TTLS — server certificate only; builds a TLS tunnel, client authenticates inside it.
  • EAP-FAST — uses a PAC instead of certificates.
  • 802.1X = port-based network access control; the RADIUS server is the authentication server.
  • Site survey + heat map = where to place APs and at what power.

Exam-day mechanics

Worth more points than any single topic

PBQ Time strategy

  • 90 questions · 90 minutes · 750 / 900 to pass.
  • PBQs come first and are Domain-4 heavy (log analysis, IR ordering, tool selection). Expect roughly 4–5.
  • Flag and skip every PBQ immediately. Clear all the multiple choice first — they are faster points — then return with the time you have left.
  • More candidates fail from sinking 15 minutes into one PBQ than from any knowledge gap.
  • Partial credit exists on PBQs. Fill in every field, even a guess.

MCQ Reading the question

  • Find the qualifier: BEST, MOST likely, FIRST. Several options will be true; only one fits the qualifier.
  • "What should the analyst do FIRST?" almost always means contain / isolate, or verify the alert is real — not eradicate.
  • Answers naming an unpatchable system point to segmentation or compensating controls.
  • Eliminate the two clearly wrong options before weighing the last two. Never leave a blank — no penalty for guessing.
