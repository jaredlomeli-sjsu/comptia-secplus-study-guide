Chapter 4 — Securing Your Network

Detection, wireless, and remote access

IDS vs IPS

Detect vs prevent — placement and method matter
Axis Option A Option B
Response IDS — detects and alerts (out-of-band, passive; sees a copy of traffic) IPS — sits inline and blocks in real time (preventive/corrective)
Scope HIDS — agent on one host; sees encrypted traffic after decryption, local files/logs NIDS — sensors watching network segments; broad view, can't see inside encrypted payloads or host activity
Method Signature-based — matches known attack patterns; low false positives but blind to zero-days (vulnerabilities with no patch/signature yet); needs constant updates Anomaly/trend-based — builds a baseline of normal, flags deviations; can catch novel attacks but higher false positives; re-baseline after network changes

Getting traffic to a NIDS: port mirroring (SPAN) — switch copies traffic to a monitor port — or a hardware network tap. An aggregator combines multiple links into one feed for the sensor.

NTA Network Traffic Analysis — the anomaly/trend-based approach above, applied specifically to network flows and packet metadata: an NTA platform baselines normal traffic patterns and flags deviations, often using the same AI/ML-assisted modeling as UEBA but focused on the wire instead of user/entity behavior.

Vocabulary: false positive = alert with no attack (noise); false negative = attack with no alert (the dangerous one). An APT (Advanced Persistent Threat) is a well-funded, long-dwell adversary — typically nation-state — that anomaly detection and threat hunting target.

Deception Technology

Four honey-things, increasing granularity
Tool What It Is Purpose
Honeypot Intentionally vulnerable-looking decoy server, isolated from production Divert attackers + observe their tools/techniques; any traffic to it is suspect by definition
Honeynet An entire fake network of honeypots Make the deception convincing for longer engagement
Honeyfile Bait file with an enticing name (passwords.xlsx) Access to it triggers an alert — detects snooping insiders/intruders
Honeytoken Bait data: fake credentials, fake API key, fake DB record Any use of the token anywhere proves a breach and traces the leak path

Wireless Fundamentals

Bands, surveys, and antennas
  • WAP Wireless Access Point — a device that lets wireless clients connect to a wired network — a rogue or misconfigured WAP is a common way attackers gain network access.
  • SSID — the network name an AP broadcasts. Disabling the broadcast hides it from casual users only — tools see it instantly (security by obscurity, not a real control). BSSID Basic Service Set Identifier — the MAC address of a wireless access point's radio, uniquely identifying that specific AP — used to distinguish access points that share the same SSID.
  • Bands: 2.4 GHz = longer range, more interference (microwaves, Bluetooth), 3 non-overlapping channels (1/6/11). 5 GHz = faster, shorter range, many channels. 6 GHz = Wi-Fi 6E.
  • 802.11 standards: b/g (2.4 GHz) → n (both bands, "Wi-Fi 4") → ac (5 GHz, "Wi-Fi 5") → ax (Wi-Fi 6/6E).
  • Site survey — walk the space with a Wi-Fi analyzer to map coverage and interference; output is a heat map. Also used defensively to find rogue APs (wireless footprinting = mapping the wireless environment).
  • Antenna choice as a control: omnidirectional radiates in all directions; directional focuses the signal — aim coverage into the building, reduce AP power so the signal doesn't bleed into the parking lot.

Wireless Security Evolution — WEP → WPA3

Know what broke and what fixed it
Generation Crypto Verdict
WEP RC4 with tiny 24-bit IVs that repeat broken — crackable in minutes via IV attacks; never use
WPA TKIP (still RC4) — stopgap for WEP-era hardware deprecated
WPA2 (802.11i) CCMP / AES Still common; PSK mode vulnerable to handshake capture + offline dictionary attacks on weak passphrases
WPA3 AES; SAE (Simultaneous Authentication of Equals — Dragonfly handshake) replaces the PSK exchange current — SAE resists offline dictionary attacks and adds forward secrecy

PSK / Personal mode

One shared passphrase for everyone. Fine at home; in business, no individual accountability and one leaver means re-keying every device.

Enterprise mode

802.1X + RADIUS: each user authenticates with their own credentials/certificate. Individual accountability, instant revocation. The AP and RADIUS server share a shared secret.

Open / OWE

Open = no encryption at all. WPA3's Enhanced Open (OWE) encrypts traffic on open networks without a password — fixes coffee-shop sniffing. A captive portal adds a web-based acceptance/payment page on top of open networks (free or paid tiers).

WTLS Wireless Transport Layer Security — a security protocol adapted from TLS for older, low-bandwidth mobile devices to encrypt data over wireless networks. A historical footnote today — modern devices just use standard TLS.

EAP Family & 802.1X

Certificate count is how you tell them apart

IEEE 802.1X = port-based network access control: nothing passes a switch port or AP until the supplicant (client) authenticates through the authenticator (switch/AP) to the authentication server (RADIUS). EAP is the framework carrying that authentication; the variants differ by who presents a certificate:

Variant Server Cert Client Cert Notes
PEAP ✔ ✘ Protects EAP inside a TLS tunnel; client uses password/ MSCHAPv2 Microsoft Challenge Handshake Authentication Protocol — exchanges a hashed challenge instead of a plaintext password
EAP-TTLS ✔ ✘ Like PEAP; supports legacy inner auth methods
EAP-FAST optional (PAC) ✘ Cisco's fix replacing LEAP; uses Protected Access Credential
EAP-TLS ✔ ✔ Most secure — mutual certificate authentication; heaviest to deploy (PKI for every client)

After authentication, client and AP derive the PMK (Pairwise Master Key) — the top-level key generated during authentication — and use it to derive the PTK (Pairwise Transient Key), the per-session encryption key that actually protects traffic. RADIUS federation extends 802.1X across organizations (e.g., eduroam lets SJSU credentials work at other universities).

Exam cue: "requires certificates on both server and clients" = EAP-TLS. "Certificate only on the server" = PEAP or EAP-TTLS.

Wireless & Short-Range Attacks

Match the name to the one-line description
Attack What Happens
Rogue AP Any unauthorized access point on the network (often an employee's convenience AP) — instant backdoor past the firewall
Evil twin Attacker's AP imitating a legitimate SSID to lure clients and harvest credentials/traffic — a rogue AP with intent
Disassociation attack Spoofed deauth/disassociate frames kick clients off — DoS, or a forced reconnect to capture the WPA2 handshake or push victims to an evil twin
WPS attack Brute-forcing the 8-digit WPS PIN (effectively ~11,000 tries; Pixie Dust is faster) → recovers the passphrase. Fix: disable WPS
Jamming Flooding the RF spectrum with noise — availability attack; locate with a spectrum analyzer
IV attack Exploiting repeating initialization vectors to recover keys — what killed WEP
Wireless replay Capture legitimate frames, retransmit them to repeat an action or assist key cracking
War driving / war flying Cruising (or droning) around discovering and mapping wireless networks; the legit version is a wireless audit
BLE Bluetooth Low Energy risk A power-efficient variant of Bluetooth used by wearables and IoT sensors, trading range and speed for battery life — the same three attacks below apply to it, just against a wider set of always-on devices
Bluejacking Sending unsolicited messages over Bluetooth — annoying, mostly harmless
Bluesnarfing Stealing data from a device over Bluetooth — the harmful one
Bluebugging Taking control of the device — backdoor, calls, messages
Bluebourne A set of Bluetooth stack vulnerabilities allowing full device takeover with no pairing and no user interaction at all — the attacker doesn't even need the device to be discoverable, making it more severe than bluejacking, bluesnarfing, or bluebugging, which all require some form of connection or victim action
NFC / RFID attacks Skimming contactless cards/badges at close range; RFID cloning duplicates an access badge → shielded sleeves, badge + PIN
Memory hook: bluejacking = junk messages; bluesnarfing = snatching data; bluebugging = planting a bug (control). Evil twin = fake SSID; rogue AP = any unauthorized AP.

Wireless Detection & Prevention Systems

The same IDS/IPS split from earlier in this chapter has a wireless equivalent, purpose-built to catch the attacks in the table above:

  • WIDS Wireless Intrusion Detection System — a system that monitors wireless traffic and airwaves for rogue access points and attacks, alerting security teams without blocking them.
  • WIPS Wireless Intrusion Prevention System — like a WIDS, but able to actively respond to wireless threats, such as disconnecting a rogue access point from the network.

VPN Architectures

Tunnel scope and IPsec modes decide the answer
Type Description
Remote-access VPN Individual user → corporate network, terminating at a VPN concentrator (dedicated device handling many encrypted tunnels)
Site-to-site VPN Gateway-to-gateway tunnel permanently connecting two offices; transparent to users
Always-on VPN Connects automatically whenever the device is on an untrusted network — removes user error
Full tunnel All traffic goes through the corporate tunnel — full inspection, more bandwidth load
Split tunnel Only corporate-bound traffic uses the tunnel; general browsing goes direct — efficient, but that traffic bypasses corporate security controls
Clientless (HTML5 portal) Browser-based TLS access to specific apps — no VPN client install needed

Protocols & modes

  • IPsec tunnel mode — encrypts the entire packet (including the original IP header); used for traffic crossing the internet (site-to-site). Transport mode — encrypts payload only; host-to-host within a private network.
  • ESP (IP protocol 50) = encryption + auth; AH (IP protocol 51) = auth/integrity only, no encryption; IKE UDP 500 negotiates the keys.
  • L2TP UDP 1701 — tunneling with no encryption of its own → always paired as L2TP/IPsec.
  • SSTP TCP 443 — TLS-based VPN; rides HTTPS so it traverses restrictive firewalls.
Scenario cue: "remote workers' personal browsing is consuming corporate bandwidth" → switch to split tunnel. "Security needs to inspect all remote traffic" → full tunnel.

NAC — Network Access Control

Health-check the device before it joins

NAC inspects a connecting device's posture — patched? AV current? firewall on? — and grants full access, quarantines to a remediation VLAN, or blocks. Applies to wired, wireless, and VPN connections.

Agent-based

Software installed on the device gives deep, continuous inspection. A permanent agent persists; a dissolvable agent runs once for the check and removes itself (good for guest/BYOD).

Agentless

No install — scans/queries the device externally. Less depth, but works for devices you can't manage (guests, IoT).

Central Authentication — RADIUS vs TACACS+ (and friends)

A guaranteed compare-and-contrast question
RADIUS TACACS+
Transport UDP 1812/1813 TCP 49
Encryption Encrypts only the password Encrypts the entire payload
AAA handling Combines authentication + authorization Separates all three A's — granular per-command authorization
Typical use Network access: wireless 802.1X, VPN Device administration (Cisco gear)
  • Diameter — RADIUS's heavier successor (telecom/4G/5G); name is a pun: diameter = 2 × radius.
  • PAP — password sent in cleartext over PPP. never
  • CHAP — challenge/response proves password knowledge without transmitting it; re-challenges periodically against replay.

Chapter 5 — Securing Hosts & Data

From hypervisors to handsets

Virtualization

Type I vs II, and the VM-specific risks
  • Hypervisor creates/runs VMs. Type I (bare-metal) runs directly on hardware (ESXi, Hyper-V server) — production. Type II (hosted) runs on top of a host OS (VirtualBox, VMware Workstation) — desktops/labs.
  • Host = physical machine; guest = each VM. Snapshot = point-in-time state you can revert to (take one before patching/testing). Replication copies VMs elsewhere for recovery.
  • VDI — desktops run centrally in the data center; users connect from thin clients (lightweight computers with minimal local processing that rely on the server for most computing tasks — easier to secure and patch centrally). Data never lives on the endpoint. The VDE Virtual Desktop Environment is the actual desktop session a user interacts with, delivered by the VDI infrastructure.
  • Containers — app-level isolation sharing one OS kernel (Docker). Lighter/faster than VMs, but weaker isolation: a kernel compromise touches every container.
VM Risk Definition / Mitigation
VM escape Attacker breaks out of a guest into the hypervisor/host — the most severe VM attack. Mitigation: patch the hypervisor promptly
VM sprawl Unmanaged, forgotten VMs accumulating unpatched → inventory + lifecycle policies
Resource reuse Memory/storage reallocated between VMs without sanitization can leak the previous tenant's data

Cloud Service & Deployment Models

Who manages what — the responsibility ladder
Service Model Provider Manages You Manage Example
IaaS Hardware, network, hypervisor OS, patches, apps, data EC2, Azure VMs
PaaS …plus OS + runtime/middleware Your code + data Heroku, Azure App Service
SaaS Everything up to the app Your data, user access Microsoft 365, Gmail
Serverless Everything, including scaling the runtime Just your function code AWS Lambda, Azure Functions

Serverless — running code on demand without managing the underlying servers; the provider handles auto-scaling for you.

Deployment Definition
On-premises Infrastructure physically owned and operated in the organization's own facility, rather than hosted in the cloud — full control, but full responsibility too. The baseline every row below departs from.
Public Shared CSP infrastructure, multi-tenant (AWS/Azure/GCP)
Private Cloud infrastructure for one organization (on- or off-premise)
Community Shared by organizations with common requirements (e.g., agencies with the same compliance regime)
Hybrid Two or more models connected — e.g., sensitive data private, burst workloads public
Multi-cloud Multiple CSPs at once — avoids vendor lock-in, multiplies management complexity

Related terms: CSP = the cloud provider; MSSP = outsourced security operations; edge/fog computing = processing data near its source (IoT) instead of round-tripping to the cloud; microservices/APIs = apps decomposed into small networked services — every API is attack surface needing authentication and rate limiting; CDN Content Delivery Network = a network of distributed servers that delivers content faster and absorbs traffic spikes.

Cloud-specific vulnerabilities — weaknesses unique to cloud environments, like misconfigured storage buckets, insecure APIs, or overly permissive IAM roles — distinct from traditional on-prem flaws.

Shared responsibility: in every model, your data and your identities remain your responsibility. The exam loves "who patches the OS in IaaS?" — you do.

Cloud Security Tooling

Acronyms with one-line jobs
Tool Job

Cloud-based DLP Stops sensitive data leaving via cloud services (uploads, shares, email)

MaaS Monitoring as a Service — a cloud-delivered service where a third party continuously monitors your infrastructure or applications and alerts you to issues, without you running the monitoring tools yourself

Endpoint Defense

AV → EDR → XDR is an escalation of scope
Layer Capability
Antivirus / EPP Endpoint Protection Platform Signature (and heuristic) detection of known malware — e.g., catches a Trojan (malware disguised as a legitimate program). EPP is the modern name for a preventive endpoint suite (antivirus, firewall, device control) that stops known threats before they execute — commonly paired with EDR below, which handles detection and response after something gets through.
EDR Endpoint Detection & Response — continuous behavioral monitoring on endpoints, threat hunting, response actions (isolate host, kill process, roll back)
XDR Extended Detection & Response — correlates endpoint + network + email + cloud telemetry into one detection/response platform
Host-based IPS (HIPS) Blocks attacks at the individual host level, inline
Application allow / block lists Allow list = only approved apps run (most restrictive, strongest); block list = ban known-bad, everything else runs
Exam cue: "prevent any unauthorized software from executing" = application allow list, not antivirus. "Correlate alerts across endpoints, email, and cloud" = XDR.

UAC User Account Control — the Windows feature that prompts for permission before allowing an action that requires administrator privileges, limiting how much malware can do even on a compromised admin account. A software-level complement to the endpoint controls above.

Hardening & Boot Integrity

Shrink the attack surface, then verify the boot chain
  • Hardening — disable unneeded services/ports/accounts, change defaults, apply secure configuration baselines, and remove unnecessary software (every installed program not in use is one more thing that can be exploited).
  • Master image (gold image) — pre-hardened, pre-configured standard image deployed to all machines: consistency + faster, safer provisioning.
  • Configuration management enforces baselines and detects drift; change management ensures modifications are reviewed/approved/documented — preventing outages from ad-hoc changes. On Windows, Group Policy is the mechanism: it lets administrators centrally configure and enforce security settings across many computers in a domain at once, and a GPO Group Policy Object is the actual container of settings that gets applied.
  • Patch management — test patches first, deploy on schedule, verify installation; the single most effective vulnerability mitigation.

Firmware & the boot chain

Term Meaning
BIOS → UEFI Legacy firmware vs its modern replacement; UEFI adds Secure Boot support. Updating firmware = flashing
MBR Master Boot Record The boot sector at the start of a legacy BIOS disk that loads the operating system; a common target for boot-level malware and rootkits — what Secure Boot exists to stop.
Secure Boot UEFI verifies the digital signature of bootloader/OS at each step — refuses to run unsigned/tampered code (stops rootkits/bootkits)
Measured Boot Each boot stage is measured (hashed) into the TPM; doesn't block boot, produces evidence
Boot attestation Those TPM measurements are reported to a remote server which decides if the device is healthy enough to join the network
Distinction: Secure Boot blocks tampered code; Measured Boot records and reports it. Attestation = a third party verifying the measurements.

OS Memory-Exploit Mitigations

Hardening isn't just services and firmware — the OS itself ships with defenses against memory-corruption exploits like buffer overflows:

  • ASLR Address Space Layout Randomization — an operating system defense that randomizes where a program's code and data sit in memory each time it runs, making memory-based exploits much harder to aim reliably.
  • DEP Data Execution Prevention — an operating system feature that marks memory regions as non-executable, blocking attackers from running injected code from data areas like the stack.
  • SEH Structured Exception Handling — a Windows mechanism for handling program errors; attackers have historically abused it to hijack program execution during a buffer overflow (an SEH overwrite attack).

TPM, HSM, Disk Encryption & DLP

Protecting data at rest and stopping it from leaking

TPM — Trusted Platform Module

Chip on the motherboard: hardware root of trust, stores keys (e.g., BitLocker's), supports measured boot. Burned-in endorsement key uniquely identifies it. Scope: one device.

HSM — Hardware Security Module

Dedicated removable/network appliance for generating, storing, and using crypto keys at scale — tamper-resistant, used by CAs and banks. (MicroSD HSM = portable form factor.) Scope: enterprise/server.

Disk encryption

FDE — full disk encryption in software (BitLocker, FileVault); keys often TPM-protected.

SED — self-encrypting drive: encryption done in the drive hardware itself, transparent and fast. Database/file-level encryption protects specific data even from OS-level access.

EFS Encrypted File System — a Windows feature that encrypts individual files and folders tied to a specific user account, distinct from whole-disk encryption like BitLocker.

Data in use

Data being processed in RAM/CPU. Protected by a secure enclave / TEE (Trusted Execution Environment) — isolated processor region even the OS can't read. Regulated data like PHI (health information, HIPAA) demands protection in all three states.

DLP — Data Loss Prevention

  • Network-based DLP — inspects outbound traffic (email, uploads) at the boundary and blocks sensitive content (SSNs, card numbers) from leaving.
  • Endpoint DLP — agent on the host controls copy/paste, printing, and removable media (block USB mass storage or allow only encrypted drives).
  • Identification methods: pattern matching, keywords, file fingerprints, classification labels.

Mobile Devices — MDM & Deployment Models

Ownership models + the MDM control list

These ownership models apply to any PED Personal Electronic Device — any personally owned electronic device (phone, tablet, smartwatch) brought into a workplace, a broader category than just BYOD phones.

Model Owns It Trade-off
Corporate-owned a.k.a. COBO — Corporate-Owned, Business-Only Company, business-only Maximum control, highest cost
COPE Company owns, personal use enabled Control + employee convenience
CYOD Employee picks from an approved list Choice within a supportable set
BYOD Employee's personal device Cheapest, hardest to secure — solve with MDM + storage segmentation

MDM (Mobile Device Management; UEM extends it to laptops/desktops/IoT) enforces: screen lock & encryption, remote wipe for lost/stolen devices, geofencing (policy by location — e.g., camera disabled inside the facility) vs GPS tagging (location embedded in file/photo metadata — an OPSEC leak), storage segmentation/containerization (work container separate and wipeable without touching personal data), app management via allow lists, and context-aware authentication (requirements adapt to location/network/time).

Mobile Risk Why It Matters
Jailbreaking / rooting Removing iOS / Android OS restrictions — disables the security model; MDM should detect and quarantine
Sideloading & third-party stores Installing apps outside the official store — bypasses vetting, prime malware vector
Custom firmware / OTA Unofficial firmware breaks the trust chain; OTA updates must come from trusted sources
Tethering / hotspot / Wi-Fi Direct The phone becomes a network path that bypasses corporate perimeter controls
Cellular connection The device's carrier (4G/5G) link — unlike Wi-Fi or Bluetooth, it bypasses corporate network controls entirely since it never touches the corporate network

Mobile Identity & Payment Vocabulary

  • SIM Subscriber Identity Module — the chip that identifies a subscriber to a mobile carrier; SIM swapping — tricking a carrier into porting your number to an attacker's SIM — is used to intercept SMS-based MFA codes.
  • ESN Electronic Serial Number — a unique identifier permanently assigned to a mobile device's hardware, historically used by carriers to identify devices on their network.
  • Mobile wallet — an app (like Apple Pay or Google Pay) that stores payment card information and uses NFC to make contactless payments, transmitting a one-time token instead of the real card number.
  • USB OTG USB On-The-Go — a USB standard letting mobile devices act as a host to connect directly to peripherals like USB drives — expands the attack surface of otherwise locked-down mobile devices.
  • SEAndroid Security-Enhanced Android — Android's built-in mandatory access control layer, based on SELinux, that sandboxes every app so a compromised app can't touch another app's data or the rest of the OS without an explicit policy allowing it.
  • Apple DEP / VPP Device Enrollment Program / Volume Purchase Program — Apple's enterprise programs for bulk-enrolling iOS devices into MDM automatically at first boot (DEP) and bulk-purchasing/licensing apps for the whole organization (VPP), instead of provisioning and buying one device/app at a time.
  • Sheep dip — an isolated, air-gapped system used to test a suspicious USB drive or device (found in a parking lot, received unexpectedly) before it ever touches a production machine — the mobile/removable-media equivalent of a sandbox.
  • Abandonware — software or firmware the vendor has stopped supporting entirely (beyond just end-of-life) but that remains installed and running, silently accumulating unpatched vulnerabilities with no path to a fix short of replacement.

Embedded Systems, IoT & ICS

Constrained devices you can't just patch
Term Definition
Embedded system Computer built into a device for a dedicated function (medical devices, vehicles, printers). A networked printer that also scans, copies, and faxes is an MFD Multifunction Device — also called an MFP Multifunction Printer — often overlooked as an endpoint even though it stores scanned documents and connects to the network.
IoT Network-connected consumer/office devices (cameras, thermostats, TVs) — notorious for default passwords and no updates → segment onto their own VLAN. A UAV Unmanned Aerial Vehicle (drone) is a physical-layer concern here too — used for surveillance, Wi-Fi sniffing, or even payload delivery near a facility.
ICS / SCADA / OT Operational Technology Industrial control systems for plants/utilities — OT is the umbrella term for hardware and software that monitors or controls physical processes; availability is paramount, so it often prioritizes uptime over patching and should be isolated from IT networks entirely. DCS Distributed Control Systems is a variant where control functions are spread across many controllers throughout a facility rather than centralized — common in manufacturing plants, alongside SCADA and PLCs.
PLC Programmable Logic Controller — a ruggedized industrial computer that directly drives ICS/SCADA machinery (valves, motors, conveyor belts); the DCS/SCADA row above is the layer that supervises many PLCs across a facility.
HMI Human-Machine Interface — the operator's control screen/panel for an ICS/SCADA system. A compromised HMI can let an attacker issue commands to physical equipment directly, so it's a high-value target despite looking like "just a monitor."
Data historian A specialized time-series database that logs every sensor reading and process value from an ICS/SCADA environment over time — used for trend analysis, compliance, and troubleshooting, and itself a target since it centralizes operational data.
AIC triad OT/ICS's reordering of the standard CIA triad (see Chapter 1) to Availability first, then Integrity, then Confidentiality — a plant going offline is far more dangerous than data being read, which is why OT favors uptime over patching.
SoC System on a Chip — CPU, memory, radios on one chip (Raspberry Pi, phones)
RTOS Real-Time Operating System — guarantees deterministic timing for control systems; not patchable like a desktop OS

Constraints to cite on the exam: low compute power (can't run strong crypto or agents), inability to patch, default credentials, long deployed lifespans. Compensating controls: network segmentation, firewalls in front, monitoring.

Low-Power & Cellular IoT Connectivity

  • Z-Wave and Zigbee — competing low-power, low-bandwidth mesh wireless protocols (Z-Wave ~900 MHz, Zigbee 2.4 GHz) used by home-automation and building sensors; devices relay each other's traffic instead of all talking straight to one hub, which extends range but widens the attack surface to every node in the mesh.
  • NB-IoT Narrowband IoT and LTE-M — carrier-grade low-power cellular connectivity standards for IoT devices that need years of battery life and wide-area coverage without Wi-Fi, trading bandwidth for range and power efficiency.

Specialized OT/Building Systems

  • BAS Building Automation System — networked control of HVAC, lighting, and elevators; often installed and managed by a facilities vendor with weaker security practices than IT, and rarely segmented from the rest of the network.
  • Smart meters — networked utility meters that report usage back to the provider; part of critical infrastructure, so a compromised fleet of them is a grid-availability risk, not just a privacy one.
  • PACS Physical Access Control System — the networked backend behind badge readers, door locks, and entry logging (ties back to the physical security controls in Chapter 9); compromising the PACS server can unlock doors that no amount of badge cloning ever could.
  • CAN bus Controller Area Network — the internal communications bus that lets a vehicle's ECUs (engine, brakes, infotainment) talk to each other; it was designed for reliability on a closed system, not authentication, so anything with access to it (including the OBD-II diagnostic port, or a compromised cellular/Wi-Fi-connected infotainment unit) can potentially inject commands to safety-critical systems.
  • EOL / legacy hardware — end-of-life means no more security patches: replace, or isolate + compensating controls. Legacy systems persist because critical software depends on them.
  • Decommissioning — before disposal: sanitize media (cryptographic erase, wipe, or physical destruction), remove from inventory, revoke its certificates/credentials. Data left on retired drives is a classic breach source.
